🌡️ Kühlketten-Überwachung API

REST API für IoT-Temperatursensoren zur automatischen Kühlkettenüberwachung

Willkommen zur Kühlketten-API

Diese API ermöglicht die Integration von IoT-Temperatursensoren zur automatischen Überwachung der Kühlkette für temperaturempfindliche Medikamente und Materialien.

Hauptfunktionen

  • ✓ Automatische Temperaturerfassung über REST API
  • ✓ Echtzeit-Validierung gegen Solltemperaturbereiche (2-8°C für Kühlschrank, ≤-15°C für Gefrierschrank)
  • ✓ Automatische Kühlketten-Unterbrechungserkennung bei kritischen Abweichungen
  • ✓ Bulk-Upload für mehrere Messwerte gleichzeitig
  • ✓ Statistische Auswertungen (Min/Max/Durchschnitt)
  • ✓ Zuordnung zu Chargen und Lagerorten

Unterstützte Sensoren

HTTP REST Sensoren

Jeder Sensor mit HTTP-Client (WiFi, Ethernet)

MQTT-fähige Sensoren

Via MQTT-to-HTTP Bridge (z.B. Node-RED)

Professionelle Kühlgeräte

Modbus TCP, BACnet via Gateway

Schnellstart

  1. API-Token generieren (siehe Tab "Authentifizierung")
  2. Sensor konfigurieren mit API-Endpunkt URL
  3. Testmessung senden
  4. Messwerte im Dashboard überprüfen

🔐 Authentifizierung

Die API verwendet Token-basierte Authentifizierung. Jeder Request muss einen gültigen API-Token im Authorization-Header enthalten.

Einzelne Messung erfassen

POST
POST {{ api_base_url }}temperature-logs/

Request Body:

{
  "device_id": "sensor-01",
  "temperature": 5.2,
  "location_id": 123,
  "batch_number": "LOT-2024-001"
}

Parameter:

Parameter Typ Pflicht Beschreibung
device_id string Ja Eindeutige ID des Messgeräts
temperature decimal Ja Temperatur in °C (-50 bis 50)
location_id integer Nein ID des Lagerorts
batch_number string Nein Chargennummer (für Zuordnung)

{
  "id": 1234,
  "batch": 42,

  "temperature": "5.20",

  "location": 123,

}

Statistiken abrufen

GET
GET {{ api_base_url }}temperature-logs/stats/?hours=24&device_id=sensor-01

Query Parameter:

Parameter Standard Beschreibung
hours 24 Zeitraum in Stunden
device_id - Filter nach Gerät (optional)
location_id - Filter nach Lagerort (optional)

Response (200 OK):

{
  "period_hours": 24,
  "avg_temperature": 5.4,
  "min_temperature": 4.8,
  "max_temperature": 6.2,
  "total_measurements": 144,
  "warnings": 3,
  "ok_measurements": 141
}

Messungen abrufen

GET
GET {{ api_base_url }}temperature-logs/?device_id=sensor-01&is_within_range=false

Filter-Parameter:

  • device_id - Filtern nach Geräte-ID
  • location - Filtern nach Lagerort-ID
  • batch - Filtern nach Chargen-ID
  • is_within_range - true/false für Sollbereich

🐍 Python (requests)

import requests
from datetime import datetime

API_URL = "{{ api_base_url }}temperature-logs/"
API_TOKEN = "{{ user_api_token|default:'YOUR_TOKEN' }}"

headers = {
    "Authorization": f"Token {API_TOKEN}",
    "Content-Type": "application/json"
}

data = {
    "device_id": "sensor-kitchen-01",
    "temperature": 5.2,
    "location_id": 123
}

response = requests.post(API_URL, json=data, headers=headers)

if response.status_code == 201:
    print(f"✅ Messung erfolgreich gespeichert: {response.json()}")
else:
    print(f"❌ Fehler: {response.status_code} - {response.text}")

🔧 Arduino/ESP32 (WiFi)

#include <WiFi.h>
#include <HTTPClient.h>
#include <DHT.h>

const char* API_URL = "{{ api_base_url }}temperature-logs/";
const char* API_TOKEN = "{{ user_api_token|default:'YOUR_TOKEN' }}";

void sendTemperature(float temp) {
  HTTPClient http;
  http.begin(API_URL);
  http.addHeader("Content-Type", "application/json");
  http.addHeader("Authorization", "Token " + String(API_TOKEN));

  String payload = "{\"device_id\":\"esp32-01\",\"temperature\":" + String(temp, 1) + ",\"location_id\":123}";

  int httpCode = http.POST(payload);

  if (httpCode == 201) {
    Serial.println("✅ Daten gesendet");
  } else {
    Serial.printf("❌ Fehler: %d\n", httpCode);
  }

  http.end();
}
